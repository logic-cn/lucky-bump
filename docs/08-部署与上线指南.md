# 部署与上线指南（需用户介入事项全清单）

> 编码与测试已在仓库完成（见 docs/DEV-PROGRESS.md），以下步骤需要 HBuilderX 与你的 DCloud 账号。

## 1. 前置条件

1. 安装 HBuilderX（4.0+，建议最新版，uni-app-x 支持）。
2. 注册 DCloud 账号并完成开发者实名认证。
3. 开通 uniCloud 服务空间（阿里云版）：[https://unicloud.dcloud.net.cn](https://unicloud.dcloud.net.cn) → 创建服务空间（推荐"基本套餐"，北京/上海区域均可）。

## 2. 工程关联（5 分钟）

1. HBuilderX 打开本仓库根目录（工程根目录含 manifest.json 即被识别为 uni-app-x 工程）。
2. `manifest.json` → 基础配置 → **重新获取 DCloud AppID**（当前为空占位）。
3. 右键 `uniCloud-aliyun` 目录 → **关联云服务空间或项目管理** → 选择第 1 步创建的空间（自动覆写 `spacex.json` 占位）。

## 3. 上传云函数与初始化数据库 ✅（2026-10-27 已由 HBuilderX CLI 完成）

**已完成**（HBuilderX v5.33 CLI，工程 lucky-bump → 阿里云空间 lucky-bump / <旧阿里云空间ID>）：
- 9 个云对象 + 3 个公共模块（lucky-auth-common / lucky-templates / uni-config-center 含正式 tokenSecret）全部上传成功（`cli cloud functions --upload all`）
- 24 张表 schema 全部上传（`--upload db --name <file>` 逐个），`--initdatabase` 完成
- 生产 tokenSecret 已生成并随公共模块部署（真实值不入 git，模板见 config.example.json）

```bash

$CLI cloud functions --list cloudfunction --prj lucky-bump --provider aliyun --cloud
```

**剩余人工步骤**：真机运行与云打包（§5）、§6 回归清单。

2. 右键 `uniCloud-aliyun/database` → **初始化云数据库**（写入 23 张表的 schema，全部已锁死 clientDB 权限，读写仅经云对象）。
3. 验证：HBuilderX 控制台或「云函数」面板对 `lucky-seed` 执行 `verifySeed` → 期望 `ok: true`（若提示 tokenSecret 未配置，见 §4）。

## 4. 生产密钥配置（上线前必须）

| 项 | 位置 | 说明 |
|---|---|---|
| tokenSecret | `cloudfunctions/common/uni-config-center/uni-id/config.json`（新建） | `{"tokenSecret": "<64 位随机串>", "tokenExpiresIn": 2592000}`。不配置时 token 用开发默认密钥（lucky-seed 会告警） |
| 短信验证码 | 同上 config.json | 可选。未配置时仅开放账号密码注册（当前默认形态） |
| 支付/推送 | 后续版本 | V1 不依赖 |

生成随机密钥：`openssl rand -hex 32`。

## 5. 运行与打包

- **真机运行**：连接设备 → 运行 → 运行到 Android/iOS 基座（首次需安装 uni-app-x 自定义基座）。
- **云打包**：发行 → 原生 App 云打包（Android 签名证书在打包面板创建/使用自有证书；iOS 需证书与描述文件）。
- **Web 发布**：发行 → 网站（uniCloud 控制台开启跨域配置）。

## 8. Web 端运行时已知限制与已落地规避（2026-10-28 端到端验证沉淀）

以下均为 HBuilderX 5.33 uni-app x（蒸汽模式）Web 端实测结论；App 端不受影响或已同步修复：

1. **uni.showModal 全部回调不触发**（success/complete/fail 均不执行）：导出提示、退出登录、移除成员、接种反应提示 4 处已替换为页面内自绘弹窗。后续新增确认/提示交互请沿用自绘弹窗，勿用 showModal。
2. **`number.toInt()` 缺失**：web 端 number 原型无 UTS 扩展方法，`main.uts` 已在 WEB 条件编译内补齐（向零截断语义）。App 端为 kotlin 原生实现，不受影响。
3. **页面内"仅使用一次的 `<input>`"编译为运行时解析的 asset 组件**（`v-uni-input`），内置组件不会全局注册 → 渲染为不可输入的空元素。`main.uts` 已在 WEB 条件编译内全局注册 Input；多 input 页面由编译器内联（`__syscom`）无此问题。
4. **`type="digit"` 输入**：部分端不支持 digit 键盘，工程内统一为 `type="number"`（6 页）。
5. **reLaunch 前写全局响应式状态**（如 `applyJourney`）会触发渲染竞态（`'set' on proxy: '_ctx'`）：登录/引导已改为"先跳转、由首页 onShow 统一拉取旅程"；宝宝组页面沿用 800ms 延迟 reLaunch 的既有模式。新增"写入全局状态后立刻跳转"的代码请遵循同一模式。
6. **开发态深链（直接刷新页面 URL）不触发页面 onShow/onLoad、且 HMR 多轮热更后模块实例可能重复**——均为 dev server 特性，发行（生产构建）无此现象。验证页面时请从真实入口导航进入。
7. **CLI 上传云函数不解析 package.json 的 file: 公共模块依赖**（GUI 行为）：工程采用"公共模块 vendor 进云对象"方案（`scripts/sync_commons.sh`），上传前请先运行同步脚本；`uniCloud-aliyun/cloudfunctions/*/common/` 为生成物（含密钥配置），不入 git。
8. **callFunction 调云对象的参数约定**：`data={method, params[]}`，params 为参数数组（平台按 `method(...params)` 展开），请求层已封装；云端 `this` 仅暴露 getUniIdToken/getClientInfo 等上下文方法，数据库一律走全局 `uniCloud.database()`。
