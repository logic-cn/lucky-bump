# 技术架构设计（架构师视角）

> 版本：v0.1 | 关联：[02-产品定位与功能架构](./02-产品定位与功能架构.md) / [04-数据模型与页面结构](./04-数据模型与页面结构.md)

## 1. 技术选型与决策记录

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| A1 | 前端框架 | **uni-app-x**（.uvue + UTS） | 用户指定；原生渲染性能好；一套代码覆盖 App(Android/iOS) + Web；DCloud 官方持续投入（2026 蒸汽模式） |
| A2 | 后端 | **uniCloud（阿里云版）** 云对象 | 用户指定；与 uni-app-x 同生态；云对象 API 形态清晰、免运维；clientDB 不直接暴露给前端（安全边界在云对象内） |
| A3 | 登录注册/用户体系 | 对齐 **uni-id 生态**自研 `lucky-id` 云对象 + 自建登录页 | **uni-starter 是 uni-app（非 uni-app-x）模板，不能直接集成**；uni-app-x 的官方等价物是 uni-id-pages-x + uni-id-co（见 uniCloud 文档）。本仓库按 uni-id 数据结构（uni-id-users）与接口语义实现，后续可通过 HBuilderX 安装官方 uni_modules 无缝替换/共存 |
| A4 | 云函数语言 | Node.js（CommonJS），零第三方依赖（token 用 node:crypto HMAC） | 可在本地 Node 直接运行与测试；不依赖 npm 源；uniCloud 上传即用 |
| A5 | 状态管理 | 自研轻量 store（UTS + Vue3 `reactive` 单例） | 规模小；避免 pinia 在 app 端的兼容不确定性 |
| A6 | 请求层 | 统一 `request.uts` 封装 `uniCloud.callFunction`，自动附带 token、拦截 TOKEN_INVALID 自动跳登录 | 等价 uniIdRouter 行为 |
| A7 | 本地验证策略 | 云对象 100% 可在本地 Node 运行（自研 uniCloud mock 运行时），前端源码按 uni-app-x 规范编写，编译需 HBuilderX | 本环境无 HBuilderX/真机，测试以"后端全量 + 端到端生命周期"为准 |

### 需用户介入清单（密钥/工具，均已留占位符）

| 项 | 位置 | 说明 |
|---|---|---|
| uniCloud spaceId/clientSecret | `uniCloud-aliyun/spacex.json`（占位） | HBuilderX 关联 uniCloud 空间后自动生成 |
| DCloud appid | `manifest.json` → `appid` | HBuilderX 重新生成 |
| 短信验证码服务商 | 云端 `lucky-id/config.json`（占位） | 接入 uni-id 同款短信配置；未配置时短信注册关闭，仅账号密码注册 |

| iOS 证书/Android 签名 | HBuilderX 云打包配置 | 打包阶段配置 |

## 2. 总体架构

```
┌─────────────────────── uni-app-x 客户端（Android/iOS/Web）───────────────────────┐
│  pages(.uvue) ── components(lbc-*) ── store(reactive 单例) ── utils              │
│        │  记录交互（两步原则）        │                                            │
│        └── utils/request.uts：uniCloud.callFunction + token 拦截 + 错误统一        │
│             （离线队列：失败记录进入本地队列，网络恢复重放 —— V1.1）                │
└──────────────────────────────────┬───────────────────────────────────────────────┘
                                   │ callFunction（云对象 RPC）
┌──────────────────────────────────▼─── uniCloud（阿里云）─────────────────────────┐
│  云对象（业务边界，全部鉴权在对象内完成）：                                        │
│   lucky-id        账户/token/资料（uni-id 兼容）                                  │
│   lucky-journey   阶段引擎：建档/孕周计算/阶段切换/哀伤模式/多旅程                   │
│   lucky-record    备孕+孕期+产后记录（周期/指标/症状/计时/恶露/EPDS…）              │
│   lucky-baby      育儿记录（喂养/尿布/睡眠/成长/疫苗/里程碑/辅食/用药）             │
│   lucky-care      产检：日程模板生成/产检记录/报告归档                             │
│   lucky-family    家庭组：邀请/角色/数据组授权                                     │
│   lucky-reminder  提醒规则与排程投影                                               │
│   lucky-data      曲线/时间线/报告聚合、数据导出                                   │
│   lucky-seed      基础数据初始化（产检模板/疫苗程序表）                            │
│  common/lucky-auth-common（token 签发校验，uni-id-common 可替换）                  │
│  数据库（MongoDB，schema 校验 + 云对象侧权限）                                     │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**安全边界**：前端只调用云对象，不使用 clientDB 直连；每个云对象方法入口统一走 `auth.requireUser(ctx)` → 校验 token → 注入 uid；所有写操作校验「journey/family 归属权」；敏感字段（同房/EPDS/情绪）服务端硬编码"仅本人"。

## 4. 关键技术设计

### 4.1 认证与 token（uni-id 兼容）

- 注册登录写入 `uni-id-users`（字段对齐 uni-id：`username/password(password_hash) nickname mobile role status register_date last_login_date`）。
- token：HMAC-SHA256 签名 `uid.exp.rand`，同时落 `lucky-token` 集合（可吊销、可单点）；有效期 30 天，滑动续期；错误码对齐 uni-id 语义（`TOKEN_INVALID`/`TOKEN_EXPIRED` 前缀），保证未来接入 uniIdRouter/uni-id-pages-x 的拦截行为一致。
- 密码 scrypt 哈希（node:crypto 原生）；登录失败限速（内存计数，生产建议换 Redis/DB 计数）。

### 4.2 阶段引擎（服务端为唯一事实源）

- `lucky-journey` 内聚：预产期计算（LMP+280d / 排卵+266d / IVF D5+261d、D3+263d / B超校正规则）、孕周换算、阶段推导（T1<14w、T2<28w、T3<37w…含多胎口径）、阶段切换事件流（前端据此刷新全部页面）、哀伤模式开关、多旅程/多宝。
- 同一套孕周/疫苗/产检规则在前端 `utils/` 有只读镜像（用于展示），服务端为准（写入时校验）。

### 4.3 记录模型（宽表 + 快照）

- 统一 `daily_logs`（一条记录 = 一个指标事件）承载离散指标，`metric_code` 区分；服务端按指标白名单校验数值结构与单位；写入时快照 `stage_week`（孕周）或 `baby_month_age`（月龄），保证孕周修正/早产矫正后历史可解释。
- 计时类（宫缩/亲喂/吸奶）独立 `tracker_sessions`（开始/结束/侧别/计量）。

### 4.4 提醒引擎

- 服务端只存规则（`reminder_rules`）并投影"未来 30 天排程"（`schedule_items`）；客户端拉取渲染，通知依赖端上本地通知（HBuilderX 打包配置），UniPush 占位。

### 4.5 测试与质量

- 云对象 100% 本地可测：`test/harness/unicloud-mock.js` 实现 `uniCloud.database()` 传统 API 子集（add/doc.set/get/update/remove/where.get/count/orderBy/limit/skip/field）+ 云对象调用协议（`cloudObj[method](ctx)`）。
- 单元测试（node:test）覆盖：token、孕周计算、产检模板生成、疫苗程序表、5-1-1 宫缩判定、EPDS 评分、成长百分位（内置 WHO LMS 简表）、授权矩阵。
- E2E：全生命周期脚本（注册→建档备孕→周期/试纸→验孕→好孕确认→孕期记录→产检→分娩→产后→育儿→二宝回流）。
- `npm test` 一键运行（CI 可用）。

### 4.6 性能与体验

- 首页数据一次聚合接口（`lucky-data.today`）返回：阶段卡+待办+快捷项+趋势摘要，减少首屏请求数。
- 记录动作本地乐观更新 + 后台同步；大图（报告）走 uniCloud 暂存（`uniCloud.uploadFile`），云对象只存 fileID。

## 5. 上线清单（含依赖用户项）

1. HBuilderX 打开工程 → 生成 appid → 关联 uniCloud 空间（回填 spacex.json）。
2. 右键 `cloudfunctions` 全部上传（含公共模块），右键 `database` 初始化（schema + db_init.json 模板数据）。
3. `lucky-seed.verifySeed` 校验基础模板已写入。
4. manifest 密钥占位逐项回填（见 §1 表）。
5. 云打包 / web 发布（`package.json` 提供了 web 构建脚本）。
6. 真机回归：计时器后台、通知权限、夜间模式。
